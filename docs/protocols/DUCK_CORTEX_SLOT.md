# Протокол ночного слота утки (DuckCortex-minimal)

**Принят спонсором:** 2026-11-25 · **Исполнитель:** zcode · **Статус:** действующий
**Прецеденты, из которых выжат:** heist1 (15.667, 5/5), tug_ws1 model_75 (31.1),
tug_full1 model_125 (145.4 → арена 118.9), лестница-REFUTED (ослепший obsnorm),
gentle-слайд (reward рос, физика умерла).

## Законы

### 1. Prereg до запуска
Фальсифицируемое предсказание (числа!) + условие опровержения, sha-коммитмент.
Смотрим вердикт по нему в конце дуги: FULFILLED / REFUTED — оба честны.

### 2. Квитанции — общая память симбионтов
Каждый значимый итог дописывается в `duck_receipts/outcome_chain.jsonl`
(append-only, prev_hash+digest). Цепь файловая и локальная — работает без сети
и без Колонии. Любая сессия дописывает свою правду в ту же цепь.

### 3. Физический судья выше всех стражей
Арена 5 сидов > reward-кривые > watch-еры. **Урок 2026-11-25**: reward рос до
59, а физический рейтинг умер 31.1 → 9.8 → −61.8 (0/5, сама в яме). Reward —
шейпинг, не истина. Дегчек дисциплины = физический скоринг.

### 4. Peak banking — пик банкуют в момент появления
Сейвы каждые 25 · физический судья на каждый чекпойнт · доминирование =
публикация (с словом спонсора). Пик, который забанкован, нельзя потерять:
125 из 400 — монстр; 325 из 400 — статичный лузер. Трижды подтверждено.

### 5. Statue-правило переписано (v2)
Запрещено убивать по фиксированной итерации или reward-кривой. Убийство
только по **физическому краху**: judge-профиль 0/5 + рейтинг ниже порога
дисциплины, или prereg-опровержение. Пример: ladder1 убит по 0 pit_won при
ослепшем нормализаторе — по своему prereg.

### 6. Multi-machine слоты
Pro и Air — независимые дуги (роллеры на Air, актёр/туг на Pro), обе:
power-check (AC обязателен) → caffeinate → prereg → dense saves → физический
судья. Слоты не конкурируют за ядра — конкурируют за право следующей дуги.

### 7. Присутствие Колонии — заявляется явно
Перед стартом слота: `curl -m 5 localhost:9090/readyz`.
- `ok:true` → в отчёте: **«Колония в работе»** (программы, советы и глубокая
  интеграция доступны; orchestration-задачи можно ставить в очередь).
- недоступна → в отчёте: **«работаем без Колонии (заявлено явно)»** — цепь
  квитанций, prereg и стражи файловые/локальные и остаются валидными. Ничто
  в этом протоколе не требует живого оркестратора; смена честно помечается.

### 8. Тихое окно с контекстом
slotguard (load < 24) + понимание, ЧЬЯ нагрузка: нагрузка спонсорских агентов
(Codex/ZCode/Cursor) — это рабочий день, не «свободная машина». Дневной слот
не стартует; если дуга горит — решение спонсора, не автомата.

### 9. Публикация — только слово спонсора
Никакой автомат не публикует в HF без прямого «да» (исключение: ранее
выданная доверенность на конкретный критерий, зафиксированная в тексте
вотчера).
